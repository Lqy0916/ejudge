# 配置页面直接编辑版

基于 `ejudge-autosave-final-source.zip` 修改。

## 修改范围

- General settings / contest.xml：保留原有页面内编辑，修复旧请求校验失败取消新输入自动保存的问题。
- Global settings / serve.cfg：7 组参数编辑弹窗全部改为原表格行内编辑。
- Language settings / serve.cfg：旧版语言页面的编译限制和语言属性两类弹窗改为行内编辑；每种语言有独立表单。新版语言导入页面本来就直接编辑，保留其原有流程。
- Problems / serve.cfg：题目标识、文件、校验、题面、Submission、编译、运行、限制、检查、计分、反馈、榜单共 12 组弹窗全部改为原表格行内编辑，覆盖抽象题和普通题。

控件直接放入原参数行，保留帮助和文件编辑链接。用于初始化的旧只读值隐藏保留，不参与新表单提交。题目的 Default/继承默认值仍使用原接口约定。

## 保存行为

转换后的参数停止输入 700 毫秒或离开输入框时保存到服务器编辑会话。所有分组共用串行队列；服务器返回成功后才更新保存快照。校验和网络错误保留输入并显示重试按钮；旧请求报错不会取消较新输入的保存。

普通页面导航和 COMMIT 会先等待所有待保存分组完成。Forget it 等待已发出的请求结束，再丢弃编辑。关闭或刷新页面时仍有未保存请求，会保留浏览器的未保存提示。这类提示不是参数编辑弹窗。

改变基础抽象题、题型、计分模式及部分影响页面结构的全局参数后，全部待保存修改完成才刷新当前页面，以重新计算服务端生成的继承默认值和条件字段，并保留当前折叠分组。

自动保存不是正式应用配置：仍需 `COMMIT changes!`。

## 配套接口修复

- 21 个现有分组保存接口在 JSON 内报告校验结果后返回成功的页面渲染状态，避免调度器以 HTML 错误页面替换 JSON。
- 修复全局主配置启用 Windows 编译目录时提前返回，导致后续字段和 JSON 响应被跳过的问题。
- 修复语言属性接口校验失败路径中 `style_checker_env` 重复释放。
- 修正全局比赛结束时间初始化选择器和高级配置 `enable_problem_history` 控件前缀。

## 测试

在源码根目录运行：

```sh
npm --prefix tests ci
npm --prefix tests test
```

本次运行共 22 项测试，全部通过。测试覆盖原 contest.xml 保存流程、新队列的并发与失败处理、COMMIT/Forget it、继承默认值、语言表单隔离，以及实际 CSP 宏和前端脚本的 DOM 初始化与控件挂载。

模板测试采用受控的服务端数据替身。本次随后在现有本地 Docker 环境中完成了全部修改页面及保存接口的 CSP 生成和 C 编译，安装并重启了 90 端口的容器。浏览器实际打开 Global settings 并点击输入框，确认控件直接出现在参数行，编辑弹窗数量为 0，浏览器控制台没有错误。91 端口保留旧版对照。

这项验证使用现有可运行镜像和测试比赛，不代表从 Dockerfile 基础镜像开始的完整重建测试，也没有访问或修改老师的远程服务器。

## 部署注意

按现有 Ejudge 环境的构建部署流程重新编译并安装本源码。不能只替换某个 CSP 文件或 JavaScript：分组页面、21 个保存接口和新增的 `style/priv_inline_edit.js` 必须一起更新。构建文件已登记新脚本和共享 CSP 依赖。

部署后重启/重载相应服务并强制刷新浏览器。验收应覆盖抽象题和继承题、多种语言、无效参数、慢网络、跨分组修改后立即 COMMIT，以及题型/基础题变更后的继承显示。
